# Borhan_SK Portfolio — راهنمای فارسی

این پروژه از نو به یک پورتفولیوی شخصی و سیستم دریافت سفارش برنامه‌نویسی تبدیل شده است. کد قدیمی Self، Telegram Desktop، Flask، Docker و Render در این نسخه وجود ندارد.

## امکانات

- سایت عمومی دو‌زبانه فارسی/انگلیسی با پشتیبانی کامل RTL/LTR
- معرفی، رزومه، مهارت‌ها، خدمات و نمونه‌کارها
- ثبت سفارش پروژه بدون نیاز به ثبت‌نام بازدیدکننده
- پیوست خصوصی مشتری (حداکثر ۱۲ مگابایت)
- فرم پیام و پشتیبانی
- ارسال نظر، پیشنهاد و انتقاد؛ فقط پس از تأیید مالک عمومی می‌شود
- ورود به پنل مالک از طریق آیکون کوچک قفل در گوشه پایین صفحه؛ با کلیک روی آن صفحه ورود ایمیل و رمز عبور باز می‌شود. پنل `/owner.html` برای مشاهده سفارش‌ها، تغییر وضعیت، ثبت قیمت/یادداشت، دریافت پیوست و بارگذاری فایل تحویل است
- مدیریت محتوای خدمات، پروژه‌ها، مهارت‌ها و پروفایل در هر دو زبان
- صفحه حریم خصوصی

## معماری

- GitHub: مخزن کد و تاریخچه تغییرات
- statichost.eu: میزبانی فایل‌های استاتیک
- Supabase: پایگاه داده، احراز هویت مالک و ذخیره فایل خصوصی

این پروژه بدون Build است. فایل `statichost.yml` مشخص می‌کند فقط پوشه `public/` منتشر شود؛ فایل SQL و مستندات در ریشه مخزن عمومی نمی‌شوند.

## مرحله ۱ — ساخت پروژه Supabase

1. وارد https://supabase.com شوید و یک پروژه جدید ایجاد کنید.
2. در بخش **SQL Editor**، محتوای فایل `supabase/schema.sql` را کامل اجرا کنید.
3. صبر کنید تا همه دستورها بدون خطا اجرا شوند.
4. از بخش **Project Settings → API** یا **Connect**، مقدار Project URL و کلید **Publishable** را بردارید. کلید جدید معمولاً با `sb_publishable_` شروع می‌شود. کلید قدیمی `anon` نیز با همین تنظیمات RLS قابل استفاده است.
5. فایل `public/assets/js/config.js` را باز کنید و این دو مقدار را جایگزین کنید:
   - `supabaseUrl`
   - `supabasePublishableKey`
6. آدرس‌های Telegram، LinkedIn، GitHub و Email را هم در همان فایل وارد کنید.

**هشدار امنیتی:** فقط کلید Publishable/anon را داخل `config.js` قرار دهید. کلید `secret` یا `service_role` را هرگز در سایت، GitHub یا چت قرار ندهید. دسترسی داده‌ها به RLS متکی است.

## مرحله ۲ — ساخت حساب مالک

1. در Supabase به **Authentication → Users** بروید و یک کاربر با ایمیل خودتان بسازید.
2. ثبت‌نام عمومی (Allow new users to sign up) را خاموش نگه دارید. سایت برای بازدیدکنندگان حساب نمی‌سازد.
3. شناسه UUID کاربر ساخته‌شده را کپی کنید.
4. در SQL Editor این دستور را با UUID واقعی خود اجرا کنید:

```sql
insert into public.site_admins (user_id, role)
values ('YOUR_AUTH_USER_UUID', 'owner');
```

5. از آیکون کوچک قفل در گوشه پایین صفحه وارد شوید؛ صفحه ورود ایمیل و رمز عبور نمایش داده می‌شود. مسیر مستقیم نیز `https://YOUR_SITE/owner.html` است.

## مرحله ۳ — بارگذاری در GitHub

1. یک مخزن جدید بسازید؛ مثلاً `borhan-sk-portfolio`.
2. تمام فایل‌ها و پوشه‌های داخل این بسته را در ریشه مخزن قرار دهید (نه اینکه خود پوشه `Borhan_SK_Portfolio` یک لایه تو در تو بماند).
3. ابتدا `public/assets/js/config.js` را با URL و Publishable Key واقعی تکمیل کنید.
4. تغییرات را در شاخه `main` ثبت کنید.

نکته: مخزن عمومی باعث می‌شود URL و Publishable Key در کد قابل مشاهده باشند؛ این طبیعی است، به شرطی که کلید محرمانه استفاده نشود و RLS درست اجرا شده باشد. اگر نمی‌خواهید کد دیده شود، از مخزن خصوصی و دسترسی SSH Deploy Key استفاده کنید.

## مرحله ۴ — میزبانی در statichost.eu

طبق مستندات رسمی، سایت استاتیک می‌تواند مستقیماً از مخزن Git منتشر شود. این پروژه به Build نیاز ندارد.

1. در https://builder.statichost.eu حساب بسازید و وارد شوید.
2. یک Site جدید بسازید و مخزن GitHub را وصل کنید.
3. شاخه `main` را انتخاب کنید.
4. Working directory را ریشه مخزن قرار دهید.
5. `statichost.yml` به‌طور خودکار `public: public` را مشخص می‌کند؛ اگر داشبورد جداگانه Output Directory خواست، مقدار `public` را وارد کنید.
6. Build command خالی باشد؛ این پروژه Build ندارد.
7. Deploy را اجرا کنید و آدرس آزمایشی `*.statichost.eu` را باز کنید.
8. فرم‌ها، تغییر زبان و صفحه `/owner.html` را تست کنید.

پلن Hobby در زمان تهیه این بسته شامل یک سایت، ۱۰ گیگابایت پهنای باند ماهانه و ۱۰۰ دقیقه Build است؛ سایت حاضر Build ندارد. پلن رایگان بدون کارت بانکی اعلام شده است. شرایط، سهمیه و دسترسی از ایران را پیش از اتکا به سرویس در داشبورد و قوانین فعلی میزبان خودتان بررسی کنید. سرویس در شرایط خود حالت Beta و ارائه best-effort بدون ضمانت SLA را اعلام کرده است.

## استفاده از پنل مالک

- **سفارش‌ها:** مشاهده اطلاعات، پیوست، وضعیت، برآورد، یادداشت خصوصی و فایل تحویل.
- **فایل مشتری:** با دکمه دریافت پیوست، لینک موقت ۱۰ دقیقه‌ای ساخته می‌شود.
- **فایل تحویل:** در فضای خصوصی آپلود می‌شود؛ پنل لینک امضاشده ۷ روزه تولید می‌کند. لینک را خودتان از طریق ایمیل یا تلگرام برای مشتری بفرستید. ارسال ایمیل خودکار در این نسخه فعال نیست.
- **پیام‌ها:** پاسخ را در پنل بنویسید و ذخیره کنید؛ دکمه «پاسخ با ایمیل» برنامه ایمیل دستگاه شما را باز می‌کند. ارسال واقعی باید توسط خودتان تأیید شود.
- **دیدگاه‌ها:** با تأیید منتشر و با رد از صفحه عمومی حذف می‌شوند.
- **پروژه‌ها و خدمات:** عنوان، خلاصه/توضیح هر دو زبان را پر کنید و گزینه انتشار را فعال کنید.
- **اطلاعات سایت:** عنوان اصلی، معرفی، موقعیت، تمرکز، فهرست مهارت‌ها (با کاما جداشده)، لینک‌ها و رزومه را به هر دو زبان تنظیم کنید.

## نکات مهم امنیت و نگهداری

- هیچ رمز عبور یا کلید محرمانه‌ای در فایل‌های استاتیک قرار ندهید.
- قبل از استفاده واقعی، تست کنید که کاربر ناشناس نمی‌تواند سفارش‌ها/پیام‌ها/پیوست‌ها را بخواند؛ SQL این بسته این دسترسی‌ها را با RLS می‌بندد.
- فرم‌ها honeypot، محدودیت اندازه فایل و cooldown ساده بر اساس ایمیل/نام دارند؛ این جایگزین CAPTCHA یا rate limiting پیشرفته نیست. در صورت افزایش اسپم، Turnstile و Supabase Edge Function اضافه کنید.
- Free Supabase ممکن است پس از یک هفته بی‌فعالیتی پروژه را Pause کند و پلن Free پشتیبان‌گیری خودکار دیتابیس ندارد. از SQL/داده‌ها به‌صورت دوره‌ای خروجی بگیرید.
- لینک فایل تحویل موقت است و پس از ۷ روز منقضی می‌شود؛ پنل هنگام بازکردن سفارش لینک تازه می‌سازد.
- نظرها در زبان اصلی ارسال‌کننده نمایش داده می‌شوند؛ متن‌های تحت کنترل مالک باید در هر دو زبان وارد شوند.
- این پروژه در این محیط با تست ایستا بررسی شده است؛ استقرار زنده، ساخت حساب Supabase، ارسال ایمیل و دسترسی واقعی از اینترنت ایران از اینجا قابل تأیید نیست.

## فایل‌های اصلی

```text
public/index.html                 سایت عمومی
public/owner.html                 پنل مالک
public/privacy.html               سیاست حریم خصوصی
public/assets/css/site.css        طراحی و واکنش‌گرایی
public/assets/css/owner.css       طراحی پنل مالک
public/assets/js/config.js        تنظیمات عمومی Supabase و لینک‌ها
public/assets/js/site.js          منطق زبان، فرم‌ها و محتوای عمومی
public/assets/js/owner.js         منطق پنل مالک
supabase/schema.sql               جدول‌ها، Storage و RLS
statichost.yml                    تنظیم انتشار پوشه public
```
